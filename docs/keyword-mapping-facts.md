# keywordMapper — 확보된 사실과 결정이 필요한 지점

> 2026-08-13 청송군 POI 48건 실호출로 확인한 것만 적는다.
> **매핑표는 아직 만들지 않았다.** 어떤 키워드 어휘로 갈지가 정해져야 만들 수 있다.

## A. 확인된 사실

### A-1. 분류체계가 **두 개** 다 채워져 온다

`areaBasedList2` / `detailCommon2` 응답에 둘 다 있고, 청송 48건 **결측 0건**이다.

| 체계 | 필드 | 청송 고유 코드 수 | 코드표 API |
|---|---|---|---|
| 구 분류 | `cat1` / `cat2` / `cat3` | 21 | `categoryCode2` ✅ 동작 확인 |
| 신 분류 | `lclsSystm1` / `lclsSystm2` / `lclsSystm3` | 24 | `lclsSystmCode2` ✅ 동작 확인 |

> **[해결]** `lclsSystmCode2` 에 `lclsSystmListYn=Y&lclsSystm1=<코드>` 를 주면
> 1~3단계가 이름까지 평면으로 한 번에 온다. 2단계 이름 문제는 이걸로 해결됐다.
> (`역사관광 > 종교성지 > 불교` 처럼 전 단계가 나온다)

### A-2. 신 분류가 청송에서 더 잘 쪼갠다

같은 POI 집합을 두 체계가 다르게 묶는다. 대표 사례:

| 구 분류 | 건수 | 신 분류가 같은 대상을 부르는 이름 |
|---|---|---|
| `A01010500` 자연생태관광지 | 9 | `NA040400` **지질공원** 8건 + 기타 |

청송은 유네스코 세계지질공원이다. 구 분류는 이걸 "자연생태관광지"로 뭉개고,
신 분류는 `지질공원`으로 따로 잡는다. **지역 정체성을 나타내는 축이 신 분류에만 있다.**

### A-4. 분포가 매우 얇다

48건 중 **21종(구) / 24종(신)** 이다. 즉 **코드 하나당 평균 2건**이고,
절반 이상이 **1건짜리**다. 매핑표를 아무리 정교하게 짜도 청송 한 곳에서는
대부분의 코드가 1~2개 POI 에만 적용된다.

## B. 결정이 필요한 지점

### B-1. [핵심] 키워드 어휘를 무엇으로 할 것인가

**이게 정해지지 않으면 매핑표를 만들 수 없다.**

키워드는 두 곳에서 동시에 쓰인다.

```
POI ──(keywordMapper)──▶ 키워드 ◀──(설문 응답)── 사용자
                            │
                            ▼
                         CP-SAT 매칭
```

즉 **키워드 어휘는 사용자 설문 문항과 같은 어휘여야 한다.** POI 쪽만 정할 수 없다.

기존 코드에 있던 `자연산책 / 역사 / 사진명소 / 음식 / 체험 / 실내 / 조용함` 은
근거 없이 지어낸 것이라 삭제했다. 새로 정해야 한다.

정할 때 걸리는 것들:

- **어르신 대상 서비스**라는 점이 어휘에 반영돼야 하는가?
  (예: `걷기 부담 적음`, `앉을 곳 있음`, `그늘` 같은 축은 분류코드에서 유도 불가능하다)
- 분류코드에서 **유도 가능한 축**과 **불가능한 축**을 섞을 것인가?
  - 유도 가능: `자연`, `역사`, `음식`, `체험`, `실내/실외`
  - 유도 불가능: `조용함`, `사진명소`, `경사도`, `화장실`
- 설문 문항 수가 몇 개인가? (키워드 수가 그에 종속된다)

### B-2. 구 분류(cat3) vs 신 분류(lclsSystm3) 중 무엇을 근거로 삼을 것인가

| | 구 분류 | 신 분류 |
|---|---|---|
| 코드표 API | `categoryCode2` | `lclsSystmCode2` |
| 청송 커버리지 | 100% | 100% |
| 청송 지질공원 구분 | ✗ (자연생태관광지로 뭉갬) | ✓ (`지질공원`) |
| 안정성 | 오래된 체계, 자료 많음 | KorService2 신규, 자료 적음 |
| 2단계 이름 조회 | 됨 | 파라미터 미확인 |

> 둘 다 쓰는 것도 가능하다(교차 검증). 다만 충돌 시 무엇을 우선할지 규칙이 필요하다.

### B-3. 코드 하나에 키워드를 몇 개 붙일 것인가

`A02010800 사찰` 하나를 두고도 `역사`만 붙일지, `역사 + 실내 + 조용함` 을 붙일지에 따라
CP-SAT 의 매칭 밀도가 크게 달라진다. **1:1 인가 1:N 인가.**

1:N 이면 "키워드 3개 중 2개 일치"처럼 정도를 따질 수 있고,
1:1 이면 매칭이 단순하지만 표현력이 떨어진다.

### B-4. 매핑되지 않는 코드를 어떻게 처리할 것인가

`AC050100 일반야영장`, `NA030500 기타자연생태`, `HS011200 기타역사유적지` 처럼
어휘에 안 맞거나 "기타"인 코드가 있다. `null` 로 둘지, `기타` 키워드를 줄지,
해당 POI 를 거점 후보에서 뺄지.

### B-5. 음식점(9건)을 거점 후보로 볼 것인가

청송 48건 중 **9건이 음식점**(`A05` / `FD`)이다. 이건 매핑 문제가 아니라
**거점 정의의 문제**다. "가이드가 상주하는 운영 거점"에 식당이 포함되는가?

포함이면 키워드 어휘에 음식 축이 필요하고, 제외면 STEP 4 판정에서 걸러야 한다.

## B-확정. 결정된 설계 (2026-08-13)

관광 선호와 운영 조건을 **하나의 `keywords[]` 에 섞지 않는다.**

```
POI
├─ preference_category   자연 / 역사·문화 / 시장·지역생활 / 음식 / 체험
├─ operability           운영시간 / 휴무일 / 화장실 / 착석 / 실내·그늘 / 접근성   ← 별도 관리
├─ classification        lclsSystm1/2/3 + cat1/2/3 (원본 코드 둘 다 보관)
└─ poi_role              GUIDE_HUB | ROUTE_STOP
```

| 결정 | 내용 |
|---|---|
| B-1 어휘 | 관광 선호 **5종**. 화장실·착석·실내·접근성은 선호가 아니라 **거점 운영 적합성**이므로 분리 |
| B-1 제외 | `경관·사진` — 분류코드에 대응 축이 없어 어휘에서 제외 (§D-1) |
| B-1 제외 | `걷기 부담`·`경사` — 관광객이 노약자라는 전제가 없고 가이드도 거점 상주형. 현장 검수에서 필요성 확인 시 운영 항목으로 추가 |
| B-2 기준 | 신 분류 `lclsSystm` 1차 → 구 분류 `cat` 보조 → 둘 다 실패 시 unmapped. 원본 코드는 둘 다 저장 |
| B-3 개수 | **코드당 주 카테고리 1개**. `역사 + 실내 + 조용함` 처럼 겹쳐 붙이면 매칭 점수가 부당하게 높아짐 |
| B-4 미매핑 | 억지로 매핑하지 않음. POI 는 삭제하지 않고 거점 후보로 남되 카테고리 보너스 없음 |
| B-5 음식점 | 기본 `ROUTE_STOP`. 업주 협의·영업시간·좌석 점유 문제로 상주 부적합. 협약된 곳만 관리자가 `GUIDE_HUB` 승격 |

## C. 구현 상태 (2026-08-13)

### 완료

| 항목 | 위치 |
|---|---|
| 코드표 고정 (cat3 153종 · lclsSystm3 246종) | `features/poi/data/categoryCodes.json` |
| 코드표 재생성 스크립트 | `scripts/fetch-category-codes.js` |
| 매핑표 + 역할 판정 | `features/poi/keywordMapper.js` |
| `lcls_systm1/2/3` 정규화 필드 추가 | `poiNormalizer.js` |
| 파이프라인 STEP 3 연결 + trace 집계 | `selectionPipeline.js` |

**매핑 단위**: 3단계 코드는 246/153종이라 전수 매핑하면 유지가 안 된다.
**2단계 코드에 매핑하고 필요한 경우만 3단계로 덮는다.**
`기타~` 로 끝나는 분류는 성격이 불명확하므로 의도적으로 `null` 로 둔다
(빠뜨린 것과 구분하기 위해 항목 자체는 남긴다).

### `기타~` 분류는 두 체계 모두에서 매핑하지 않는다

`isCatchAllName()` 으로 3단계 분류명이 `기타` 로 시작하면 매핑을 막는다.
하드코딩 목록이 아니라 규칙이라 코드표가 갱신돼도 자동으로 적용된다.

분류기가 상위 항목에 못 넣어 남긴 자리라 실제 내용을 알 수 없다.
상위 2단계가 방향을 알려주긴 하지만, 그 신뢰로 카테고리 보너스를 주면
검증되지 않은 매칭이 된다.

> **신 분류에서만 막으면 구 분류 폴백이 되살린다.** 그래서 양쪽 모두에 적용한다.

### [OPEN·보류] `시장·지역생활` 은 현재 수집 조건상 절대 나오지 않는다

4개 지역 모두 0건인데 카테고리 문제가 아니라 **수집 조건 문제**다.
기본값이 `contentTypeIds = [12, 14, 28, 39]` 인데 **쇼핑은 `38`** 이라 애초에
수집되지 않는다. 경주에서 `38` 만 따로 수집하면 매핑은 정상 동작한다:

```
감포공설시장     시장·지역생활   쇼핑 > 시장 > 비상설시장
수협 활어직판장   시장·지역생활   쇼핑 > 전문매장/상가 > 전문상가
경주 중앙시장     시장·지역생활   쇼핑 > 시장 > 상설시장
```

**결정 보류.** 전통시장을 가이드 상주 거점으로 볼 것인지의 문제다.
앉을 곳·화장실이 있는 편이라 거점으로 적합해 보이지만, 상인 영업 공간이라
음식점과 같은 협의 문제가 생길 수 있다.
`38` 을 수집 대상에 넣지 않으면 이 카테고리는 계속 빈 채로 남는다.

## D. 매핑하면서 내가 판단한 것 — 검토 필요

코드에 `[검토필요]` 주석으로 표시해 두었다. 근거가 약한 것들이므로 확인이 필요하다.

### D-1. [해결] `경관·사진` 은 어휘에서 제외

`자연 / 역사·문화 / 음식 / 체험 / 시장·지역생활` 은 분류코드에서 바로 유도되는데
**`경관·사진` 만 유도되지 않았다.** "사진 찍기 좋은 곳"은 분류 축이 아니라
장소의 성질이라 코드에 표현돼 있지 않다.

유일한 후보였던 `VE01 랜드마크관광` 은 하위를 열어 보니
`건물 / 타워·전망대 / 다리 / 분수 / 동상 / 터널 / 댐 / 등대` — 인공 구조물이었다.
구 분류의 `A0205 건축/조형물` 과 같은 성격이라 **역사·문화로 배정**했다.

**어휘를 5종으로 확정한다.**

> 청송의 `지질공원 8건`(주상절리·기암단애 등)은 사진 명소 성격이 강하지만
> `자연` 으로 남는다. 나중에 사진 명소 축이 필요해지면 분류코드가 아니라
> 다른 신호(`detailImage2` 이미지 수, 관리자 검수)로 별도 속성을 만들어야 한다.
