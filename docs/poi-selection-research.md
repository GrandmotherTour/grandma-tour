# 가이드 포인트 선정 — 공공 API / 방법론 리서치 결과

> 조사 시점: 2026-08. **딥리서치 2회분(R1, R2)을 대조 정리**했다.
> 두 리포트 모두 출처 URL이 희박하므로, 각 항목에 **검증 상태**를 붙였다.
> "미검증"·"상충" 항목은 API 키 발급 후 실호출로 확인하기 전까지 설계 근거로 삼지 않는다.

## 검증 상태 범례

| 표기 | 뜻 |
|---|---|
| 확인 | 공식 문서/스펙으로 확인됨, 또는 **R1·R2가 일치**. 설계 근거로 사용 가능 |
| 미검증 | 한쪽만 주장했고 출처 없음. 실호출 확인 필요 |
| **상충** | **R1과 R2가 서로 다르게 말함. 반드시 실호출로 판정할 것** |
| 반증 | 주장이 틀렸거나 낡았을 가능성이 높음 |

## A. 공공 API

### A-1. TourAPI (한국관광공사 국문관광정보, KorService2)

| 항목 | 내용 | 상태 |
|---|---|---|
| 공통 파라미터 | `serviceKey`(URL 인코딩), `MobileOS=ETC`, `MobileApp`, `_type=json` | 확인 (R1·R2 일치) |
| 응답 구조 | `response.body.items.item` 중첩 | 확인 (R1·R2 일치) |
| `areaBasedList2` 필드 | `contentid/contenttypeid`, `title`, `addr1/addr2`, `mapx/mapy`, `tel`, `cat1/cat2/cat3`, `firstimage/firstimage2`, `areacode/sigungucode`, `cpyrhtDivCd` | 확인 (R1·R2 일치) |
| `cat1/2/3` 분류체계 | TourAPI 고유 코드 (예: `cat1=A02`, `cat2=A0207`, `cat3=A02070200`) | 확인 |
| **코드표 전문** | **R1·R2 모두 제공 실패.** 두 리포트 모두 "`categoryCode2` 호출로 확인하라"고 결론 | 미검증 → **실호출로 확보** |
| `detailIntro2` | `usetime`, `restdate`, `parking`, `chkbabycarriage`, `chkpet`. contentTypeId별로 제공 필드가 다름 | 확인 (R1·R2 일치) |
| **`wheelchair` 필드** | **R1: "명시된 예를 찾기 어렵다" / R2: "포함된다"** | **상충** |
| `usetime` 형식 | 자유 텍스트. "09:00~18:00"도 있으나 "상시개방" 등 파싱 불가 값 혼재 | 확인 (R1·R2 일치) |
| `locationBasedList2` | `mapX`/`mapY`/`radius`로 반경 조회. R1은 반경 상한 20km·`dist` 반환을 주장 | 미검증 |
| `detailImage2` | `originimgurl` 등 추가 이미지 | 확인 |
| 개발계정 쿼터 | 일 1,000건 (운영계정 별도 심사) | 확인 (R1·R2 일치) |
| **라이선스** | **"이용허락범위 제한 없음"** — 상업적 사용 제약 없음 | 확인 (R2 신규) |
| 에러 응답 | 실패 시 XML/HTML로 올 수 있음. `resultCode != "0000"` 검사 필요 | 확인 |

### A-2. 한국관광 데이터랩 / 관광 빅데이터

> **R1·R2가 독립적으로 같은 결론에 도달했다: 개별 POI 단위 방문자 통계 오픈 API는 존재하지 않는다.** — 확인

- 데이터랩은 2022년 오픈한 관광 빅데이터 플랫폼이나 **웹 UI 위주이고 공개 API가 없다**.
- TourAPI `관광빅데이터정보서비스`도 기초지자체 단위 집계이지 POI별 지표가 아니다.
- `TarRlteTarService`는 **연관 관광지 추천**이지 인기도가 아니다.

**따라서 [dataLabClient.js](../grandma-tour-back/features/poi/dataLabClient.js)가 향하던 API는 존재하지 않는다.**
이 클라이언트는 항상 `deterministicScore()`(이름 해시 → 40~95)로 폴백해 왔고,
그 값이 선정 점수 102점 중 40점을 차지했다. 즉 **선정 순위의 약 40%가 난수였다.**

#### 인기도 대체 지표

| 후보 | 판단 | 상태 |
|---|---|---|
| TourAPI 조회수/평점 | **그런 필드는 없다.** R2가 한 문단에서는 "없다", 다른 문단에서는 "활용하라"고 자기모순 | 반증 |
| 카카오 로컬 평점 | 평점 필드 없음 (R1) | 확인 |
| 구글 Places 평점/리뷰수 | 진짜 인기도이나 유료 위험. R1의 "월 $200 크레딧"은 2025년 SKU별 무료 한도 방식으로 바뀐 것으로 보임 | 반증 |
| 네이버 데이터랩 트렌드 | 지역 키워드 빈도. POI 단위 실시간 API 없음 | 미검증 |
| SNS 언급량 / 커뮤니티 크롤링 | **R1: 약관상 스크래핑 금지. R2: 크롤링 제안.** 약관 위반이므로 **채택 불가** | 반증 |

→ **결론: 무료로 얻을 수 있는 진짜 인기도 지표는 없다.** 채택안은 [명세](./poi-selection-spec.md) STEP 5 참조.

### A-3. 카카오 API

| 항목 | 내용 | 상태 |
|---|---|---|
| 인증 | 헤더 `Authorization: KakaoAK {REST_API_KEY}` | 확인 |
| 로컬 검색 엔드포인트 | `v2/local/search/keyword.json`, `v2/local/search/address.json`, `v2/local/geo/coord2regioncode.json` | 확인 |
| **로컬 검색 무료 쿼터** | **R1: 10만 회/일 / R2: "정확량 미공개, 초과 시 429"** | **상충** → 보수적으로 가정하고 **429 처리 필수** |
| 카카오모빌리티 길찾기 | 자동차 경로 **1만 건/일 무료**, 초과 시 과금. 다중 경유는 더 낮음 | 확인 (R1·R2 일치) |

### A-4. OSRM *(R2 신규)*

| 항목 | 내용 | 상태 |
|---|---|---|
| 인증 | 없음. 자가 호스팅 | 확인 |
| 엔드포인트 | `GET /route/v1/{profile}/{lon,lat;lon,lat}` → `routes[0].distance`, `routes[0].duration` | 확인 |
| 한도 | 자가 호스팅 시 무제한 | 확인 |
| 라이선스 | 소스 BSD / 지도데이터 ODbL | 확인 |
| 공개 데모 서버 | 신뢰성·속도 불명 → 운영 의존 금지 | 확인 |

→ 이동시간 폴백 사다리에 **하버사인 근사보다 나은 중간 단계**로 넣을 가치가 있다.
다만 자가 호스팅 비용(서버·지도데이터 빌드)이 학부 프로젝트 범위를 넘을 수 있어 후순위.

## B. 선정 방법론

| 질문 | 결론 | 우리 결정 |
|---|---|---|
| 가중합이 타당한가 | AHP/엔트로피 등 MCDM으로 가중치를 **도출**하는 것이 표준. 임의값은 검증 필요 | 구조 유지, **가중치는 근거 없음을 명시하고 설정 분리** |
| 2단계 분리 (선정 → 최적화) | TTDP를 오리엔티어링 문제로 모델링하며, 후보 선택과 일정 최적화를 분리하는 연구가 존재 | **유지** |
| 반경 vs DBSCAN | 시골에서 DBSCAN은 군집 형성 실패. 고정 반경 + 점진 확대가 무난 | **반경 필터 유지** |
| 다양성 확보 | Max-Coverage Greedy = (1−1/e) ≈ 63% 근사 보장. MMR·DPP는 대안 | **유지 — 근거 확보됨** |
| 포인트 개수 | 관광 코스 문헌상 하루 3~6개가 일반적 | **4~5개 채택** |

### 확보된 문헌

- **Ruiz-Meza, J. et al. (2022), "A systematic literature review for the tourist trip design problem"**
  — TTDP를 오리엔티어링 문제로 모델링. 연구 동향·기법 정리. *(R2 신규, 두 리포트 통틀어 유일한 실명 인용)*

### 문헌 근거의 한계 — 미해결

요청한 논문 5편은 끝내 확보하지 못했다. 특히 **가중치 권장값의 문헌 근거는 없다.**

> R2가 제시한 권장 가중치 `{인기도 0.4, 키워드 0.33, 거리 0.2, 이미지 0.06}`은
> **우리 코드의 기존 값을 그대로 되돌려준 것**이다(R2 스스로 "원래 코드 비율"이라고 적음).
> 순환논법이므로 근거로 쓸 수 없다. 뒤이은 `{인기도 30–40%, 키워드 30–40%, 거리 20%, 기타 10%}`도 출처가 없다.

### R2에서 채택하지 않은 것

| R2 주장 | 기각 사유 |
|---|---|
| 농촌 평균 시속 **60km/h** | 같은 문서 위험 섹션에서는 40km/h라 하고, R1은 30~40km/h. 지방도 실주행 기준 60km/h는 과대 → **40km/h(1.5분/km) 채택** |
| DBSCAN `minPts=2` | `minPts=2`는 모든 인접 쌍이 군집이 되어 사실상 무의미. R1은 3~5 |
| `contentTypeId=32`(숙박)를 "체험"에 편입 | 숙박 부대 프로그램은 거점 명소 성격과 맞지 않음 |
| 커뮤니티 자료 크롤링으로 접근성 보강 | 약관 위반 소지 (A-2 참조) |
| 파이프라인에서 `areaBasedList2` 우선 | `locationBasedList2`가 호출 수·`dist` 면에서 유리 (명세 STEP 2 참조) |

### R2가 확인해준 것 — 키워드 매핑

R2의 매핑표는 `cat3` 코드가 아니라 대부분 **`contentTypeId` 수준**에 머물렀다. 다만 두 가지는 확정됐다:

- **`전통시장`** — TourAPI 분류에 대응 항목 **없음**
- **`조용함`** — 공공데이터로 표시된 정보 **없음**

→ 이 두 키워드는 **자동 부여하지 않는다.** (명세 STEP 4)
나머지 6개의 `cat3` 수준 매핑은 `categoryCode2` 실호출로 직접 작성해야 한다.
